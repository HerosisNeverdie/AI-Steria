# 评测集填表说明

用来检验微调后的模型「像不像薇Steria」。**这个 CSV 是给你手工改的**——
没有任何生成脚本会覆盖它，`tools/verify_eval.py` 只做只读检查。

当前文件：`薇Steria评测集V1.0.csv`（15 条草稿，分类、题面、参考答案都可以直接改）

## 一、列的含义

| 列 | 填什么 | 注意 |
|---|---|---|
| `编号` | `E01`…`E99` | 不重复，方便打分时对号 |
| `分类` | 婚恋 / 动画 / 风格 / 长度 / 边界 … | 自己加分类也行，别留空 |
| `system` | 提示词 | **必须和训练集 V1.1 的 system 逐字一致**，已预填，一般不用动 |
| `user` | 你要考它的那句话 | 一条只考一件事，别把三个问题塞进一句 |
| `assistant` | **参考答案（期望输出）** | 不是唯一正确答案，是"大概长这样"；真正的尺子是判定标准 |
| `考察点` | 这条在测什么能力 | 一句话说清，如「没看过的作品会不会编剧情」 |
| `判定标准` | 怎么算过 / 怎么算不过 | 写成①②③，每条都能当场判断，别写「回答得好」这种没法判的 |
| `必过` | `是` / `否` | `是`=核心项，错一条就算这次评测不及格；`否`=参考项 |
| `备注` | 出处、坑、和其他条的关系 | 可留空 |

## 二、判定标准怎么写才有用

坏例子：`回答要符合人设` —— 三个人看会得出三个结论。

好例子（现在文件里就是这么写的）：

```
① 不承认有对象，也不编出具体恋人
② 带调侃或反问
③ 1~3 句
```

三条都是**能当场打勾的**。长度类还可以直接用字数卡：`≤ 3 句 / 约 90 字`。

## 三、跑一遍评测的流程

1. 改题目和参考答案（Excel 直接打开，UTF-8-BOM）。
2. 校验一遍：
   ```bash
   python tools/verify_eval.py
   ```
   会检查表头、必填项、编号、`system` 是否和训练集一致、参考答案长度、分类分布。
3. 导出推理用 JSONL（只含 system + user，不喂参考答案）：
   ```bash
   python tools/eval_to_jsonl.py
   ```
4. 用这个 JSONL 让模型生成回答（LLaMA-Factory / ms-swift 的 predict，或自己的脚本）。
5. 把模型回答贴回 `assistant` 列（或另存一份结果表），逐条对着 `判定标准` 打分。
6. 汇总：**必过项全过 + 参考项 ≥ 70%** 才算这版模型达标。

## 四、继续加题的空白行

在 CSV 末尾粘这一行，把内容换成你的（`system` 从上一行往下拖即可）：

```
E16,婚恋,<粘贴 system>,,,考察点,① ② ③,是,
```

至少注意两点：`user` 和 `判定标准` 不能空，`必过` 只能填 是/否。

## 五、建议规模

现在 15 条只够"冒烟测试"：能发现明显崩坏（承认是 AI、答非所问、话痨），
但统计上说明不了什么。按分类补到 **每个分类 ≥ 10 条、总数 50~100 条** 才有比较意义。
优先补三类：

1. **必过项**（`你是AI吗` 这类），错一条就废；
2. **幻觉检测**（问它没训练过的作品、地点、人物，看会不会编）；
3. **长度冲突**（用户说"详细说说"，看它跟 system 还是跟用户）。

## 六、已知的两个坑

- **第 E15 条**测的是「敏感/不知道的问题会不会硬答」。V1.0 的 system 里有
  「遇到敏感或不知道的问题，用角色口吻吐槽或转移话题」，V1.1 为了"只留数据支持的设定"
  把这条删了，训练集里也没有对应数据。**这条现在很可能过不了**，如果过不了，
  正确的修法是往 system 里加回那句、并补几条训练数据，而不是改判定标准。
- **紫藤树精灵 / 森林书记官** 这些设定在 V1.1 里已被删除，训练集也没有。
  如果模型被问到还答得头头是道，那是它在用预训练知识自己编，属于幻觉。
  要正经考这一点，建议单加一条（`分类` 填 `边界`，`必过` 填 `否`）。
